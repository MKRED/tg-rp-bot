# Каталог компонентов tgui

Справочник компонентов `@telegram-apps/telegram-ui` (далее **tgui**) для вёрстки webapp. Цель — единый
визуальный стиль во всём приложении: весь UI собирается из одних и тех же типографики/примитивов tgui,
а не из точечного CSS, который со временем расходится по размерам/весам шрифта.

**Правило (mandatory, см. CLAUDE.md → «Структура и размер файлов» и общий раздел конвенций):**
1. Любая новая вёрстка или правка существующей в `webapp/` в первую очередь ищет готовый компонент tgui
   ниже — и текстовые узлы, и структурные блоки (списки, карточки, формы, оверлеи).
2. Если подходящего компонента tgui нет — собираем свой в `shared/components/<Name>/`, но **максимально
   переиспользуя примитивы tgui внутри него** (Typography для текста, `Cell`/`Section` для структуры и
   т. д.), а не голый `<div>`/`<span>` с CSS с нуля. Свой компонент — обёртка/композиция, не замена.
3. Голый `font-size`/`font-weight` в CSS на текстовом узле — сигнал, что где-то пропущен шаг 1: см.
   `Text`/`Subheadline`/`Caption`/`Headline`/`Title`/`LargeTitle` в разделе 1. Обоснованные исключения —
   функциональные `<textarea>`/`<input>`, одиночные глиф-символы (напр. `−`/`+` в степпере), контент с
   жёстким пиксельным бюджетом (узлы React Flow) — см. примеры по коду, где это уже применено.

Где смотреть детали поведения/пропсов и типичные ловушки конкретных компонентов (не что компонент делает,
а как он себя ведёт на практике) — [docs/telegram-ui.md](./telegram-ui.md): гоча `Section`+`Divider`
(§1.4.2), `Button` без гуттера (§1.4.3), ripple `Cell`/`Tappable` перекрывает клики (§1.4.4), фон поля vs
карточки (§1.4.1). Источники: [репозиторий tgui](https://github.com/Telegram-Mini-Apps/TelegramUI),
[песочница компонентов](https://tgui.xelene.me/).

## 1. Типографика (`Typography/*`)

Ядро правила «единый стиль» — весь текст идёт через один из этих компонентов, а не через сырой `<span>`/
`<p>` с CSS-размером шрифта.

| Компонент | Размер/вес по умолчанию | Для чего |
|---|---|---|
| `LargeTitle` | 34px/41px, `weight="1"` (700) | Заголовок экрана верхнего уровня (редко нужен в Mini App с компактными страницами) |
| `Title` | по `level`: `1"`=28px, `"2"`=22px, `"3"`=20px | Заголовки секций страницы |
| `Headline` | 17px/22px, `weight="2"` (600) | Подзаголовок между `Title` и обычным текстом |
| `Text` | 17px/26px, `weight="3"` (400, обычный) | Базовый текст — параграфы, обычные подписи, содержимое карточек |
| `Subheadline` | `level="1"`=16px/24px, `level="2"`=15px/22px | Заголовки шапок панелей/штор (`level="1"`), лейблы кнопок/тумблеров среднего размера (`level="2"`) |
| `Caption` | `level="1"`=13px/20px, `level="2"`=11px/16px | Мелкие подписи: таймстемпы, счётчики, хинты под полем, вспомогательный текст в карточках |
| `Blockquote` | — | Блок цитаты с боковой полосой |

Общие пропсы:
- `weight`: `'1'` (700), `'2'` (600), `'3'` (400, по умолчанию).
- `Component` — рендерит любой HTML-тег (`span`, `p`, `div`, `label`, …), сохраняя типографику; `caret`
  для декоративной стрелки в `Subheadline`/`Headline`.
- `TypographyProps extends AllHTMLAttributes<HTMLElement>` — можно прокидывать `onClick`, `style`,
  `className` и т. д. как в обычный элемент.

**Важно:** класс веса/размера у Typography задаёт `font-size`/`font-weight` явно (не наследуется), то
есть перекрывает родительский CSS-каскад. Если текст уже обёрнут в Typography, родительский `font-size`
CSS на нём — мёртвый код, убираем его, а не оставляем «на всякий случай».

## 2. Структура и списки (`Blocks/*`)

| Компонент | Для чего |
|---|---|
| `Section` | Карточка-группа с необязательными `header`/`footer`; сама вставляет `Divider` между прямыми детьми (гоча — см. telegram-ui.md §1.4.2) |
| `Cell` | Строка списка: `before`/`children`(title)/`subtitle`/`subhead`/`description`/`hint`/`after`. `subtitle`/`subhead` уже обёрнуты в `Subheadline` и обрезаются в одну строку сами (без `multiline`) — свой `Typography`/truncation CSS поверх не нужен. `hint` — НЕ обёрнут (голый `span`), если нужен нетривиальный размер — оборачивать вручную |
| `ButtonCell` | `Cell`, стилизованная как кнопка-действие в списке (напр. деструктивное действие в подвале секции) |
| `Info` | Компактная строка «лейбл + значение» внутри `Cell`-подобной раскладки |
| `Navigation` | `Cell` со стрелкой-шевроном для перехода на подстраницу |
| `List` | Обёртка-список без карточного фона `Section` |
| `Card` | Карточка-контейнер без семантики `Cell` (произвольный контент) |
| `Placeholder` | Экран-заглушка (пусто/ошибка/загрузка) с иконкой, заголовком и описанием |
| `Banner` | Промо/уведомление-плашка с заголовком, текстом и опциональным действием |
| `Accordion` | Раскрывающийся блок |
| `Steps` | Индикатор шагов мастера/визарда |
| `Timeline` | Вертикальная лента событий с маркерами |
| `InlineButtons` | Ряд компактных круглых кнопок с подписью (как в профиле контакта Telegram) |
| `Avatar` / `AvatarStack` | Аватар (инициалы/картинка) / стопка перекрывающихся аватаров |
| `Badge` | Маленький бейдж-индикатор (счётчик, точка-статус) |
| `Image` | Картинка с поддержкой `Badge`-оверлея и фоллбэка |
| `IconButton` / `IconContainer` | Кнопка-иконка без текста / контейнер-обёртка для иконки с фоном |
| `Button` | Основная кнопка (`size`, `mode`, `stretched`); **не несёт своего гуттера** внутри `Section` — см. telegram-ui.md §1.4.3, паттерн `SectionActions` |

## 3. Формы (`Form/*`)

| Компонент | Для чего |
|---|---|
| `Input` | Однострочное поле ввода |
| `Textarea` | Многострочное поле |
| `Select` | Нативный `<select>`-обёртка в стиле tgui |
| `Multiselect` / `Multiselectable` | Мультивыбор с чипами / отдельный чекбоксоподобный пункт мультивыбора |
| `Checkbox` / `Radio` / `Switch` | Стандартные бинарные/групповые контролы |
| `Selectable` | Обёртка-пункт для кастомных списков одиночного выбора |
| `Slider` / `Rating` | Ползунок диапазона / рейтинг звёздами |
| `Chip` | Компактный тег/фильтр (клик или удаление) |
| `PinInput` | Ввод PIN/OTP-кода посимвольно |
| `ColorInput` | Выбор цвета |
| `FileInput` | Загрузка файла |

## 4. Обратная связь (`Feedback/*`)

| Компонент | Для чего |
|---|---|
| `Spinner` | Индикатор загрузки (`size="s"`\|`"m"`\|`"l"`) |
| `Skeleton` | Заглушка-плейсхолдер контента на время загрузки |
| `Progress` / `CircularProgress` | Линейный / круговой прогресс-бар |
| `Snackbar` | Всплывающее уведомление снизу (в проекте — через `ToastProvider`, см. telegram-ui.md §1.5) |
| `Spoiler` | Затемнённый/скрытый до клика контент |

## 5. Навигация (`Navigation/*`, `Layout/*`)

| Компонент | Для чего |
|---|---|
| `SegmentedControl` | Переключатель из нескольких сегментов (аналог iOS segmented control) — в проекте своя обёртка `shared/components/SegmentedToggle` поверх Typography, см. §7 |
| `TabsList` / `Tabbar` | Список вкладок внутри страницы / нижний таббар навигации приложения |
| `Link` | Текстовая ссылка в стиле tgui |
| `Breadcrumbs` | Хлебные крошки |
| `Pagination` / `CompactPagination` | Постраничная навигация (полная / компактная) |
| `FixedLayout` | Контейнер, прибитый к краю вьюпорта (шапка/подвал поверх скролла) |

## 6. Оверлеи (`Overlays/*`)

| Компонент | Для чего |
|---|---|
| `Modal` | Модальное окно/шторка (портал — учитывать §1.5 telegram-ui.md, дерево `AppRoot`) |
| `Popper` | Позиционируемый всплывающий блок (базовый примитив для кастомных поповеров) |
| `Tooltip` | Всплывающая подсказка у элемента |

## 7. Прочее (`Misc/*`, `Service/*`)

| Компонент | Для чего |
|---|---|
| `Divider` | Горизонтальная линия-разделитель (внутри `Section` вставляется автоматически, см. telegram-ui.md §1.4.2) |
| `AppRoot` | Корневой провайдер темы/платформы — один раз на всё приложение (уже подключён, см. telegram-ui.md §1.2) |
| `Tappable` | Базовый примитив «нажимаемая область» с ripple/opacity-фидбеком (на нём построены `Cell`/`Button`) |
| `VisuallyHidden` | Элемент, скрытый визуально, но доступный скринридеру |

## Когда своего компонента не избежать

В `webapp/src/shared/components/` уже есть примеры композиции поверх tgui-примитивов вместо готового
tgui-компонента под конкретную задачу — ориентир для новых:

- `SegmentedToggle` — обёртка над кастомной кнопочной раскладкой, но лейблы внутри — `Subheadline`.
- `HintedInput` — `Input` + подпись-хинт (`Caption`), сгруппированные так, чтобы `Section` не вставил
  между ними лишний `Divider` (см. telegram-ui.md §1.4.2).
- `SectionActions` — гуттер для `Button` внутри `Section` (§1.4.3 telegram-ui.md).
- `RpText` — не обёртка над tgui, а парсер разметки ролеплей-текста (курсив/действия); используется
  **внутри** `Text`/`Caption` как children, а не вместо них.
- `TranslateSheet`, `PageStateBoundary`, `DropdownPicker` и т. п. — компонуют `Cell`/`Section`/
  `Spinner`/Typography под конкретный доменный сценарий, не изобретая новую типографику или карточную
  раскладку с нуля.

Свой компонент оправдан, когда нужна доменная логика/состояние (не просто вид), фиксированный пиксельный
бюджет (напр. узел графа веток, `webapp/src/shared/graph/treeLayout.ts`), либо контент вне дерева
`AppRoot` (портал в `document.body` — лайтбокс, кроп-редактор, см. telegram-ui.md §1.5, где tgui-стили
всё равно не долетят).
