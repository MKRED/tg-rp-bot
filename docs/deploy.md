# Деплой — инфраструктура

Процесс команды «Задеплой» (гейт → ветка `deploy`) описан в CLAUDE.md. Здесь — как устроен прод.

Прод — **один Docker-контейнер** на сервере (`https://miniapp.aoshi.ru`): тот же процесс Node раздаёт
и HTTP API, и собранную статику Mini App (webapp вшит в образ). `Dockerfile` лежит **в корне**, контекст
сборки — корень монорепо (`docker build -f Dockerfile .`).

**CI/CD:** пуш в ветку **`deploy`** запускает GitHub Action (`.github/workflows/deploy.yml`), который
собирает образ **на демоне сервера** через docker context (SSH), без реестра (GHCR не используется),
и перезапускает контейнер по `docker-compose.yml` (он лежит на сервере, в репо — справочная копия).

**Миграции БД** применяет тот же Action — шаг «Migrate DB» между сборкой и перезапуском:
`docker compose run --rm bot yarn drizzle-kit migrate` одноразовым контейнером из нового образа (тот же
`env_file` и сети). Упала миграция — шаг падает, перезапуска нет, старый контейнер работает на нетронутой
схеме. Между миграцией и перезапуском — несколько секунд, когда старый код видит новую схему: добавления
безвредны, а удаления/переименования в это окно могут ронять запросы к затронутой таблице. Поэтому
такие миграции руками заранее не применяются (правила — CLAUDE.md, «DB schema changes»).
Подробности инфраструктуры сервера — в auto-memory `server-deploy-setup`.

**Edge-nginx** (контейнер `nginx`, конфиг `/mnt/ssd/dockerdirs/nginx/conf.d/miniapp.aoshi.ru.conf` на сервере)
проксирует всё на контейнер бота. В HTTPS-блоке нужен `client_max_body_size 16m;`: по умолчанию nginx режет
тело больше 1 МБ (413), а через него идут картинки — ответ агента ComfyUI с результатом генерации (~2 МБ PNG
в base64) и прикреплённые к холсту картинки. Тот же порядок величины — `JSON_BODY_LIMIT` в `bot/src/main.ts` (8 МБ).
После правки: `docker exec nginx nginx -t && docker exec nginx nginx -s reload`.
